# FCC/NIM live qualification — 2026-09-06

The existing user-provided NIM key was configured through FCC's local Admin API,
and a live NVIDIA inference and a read-only Claude Code task passed. The key was
read from a private local file; no credential value or raw transcript is included
in this report or the public evidence.

This ran on Windows 11 x64 build `10.0.26200`, using the installed Latchkit
`1.0.0-dogfood.20260906.3` from commit
`d6ee85d8aff58c3159aaaca2b5aa7c83f8dcc509`, its private Node `24.20.0`, FCC `5.22.8`
at pin `c9b75088b09cbd3251d1e828b710cfdcd1ff3c5a`, and Claude Code `2.1.258`.

## Configuration and inference

The installed `runWithFccClaudeEnvironment` bridge verified the owned FCC
controller and authenticated endpoint before each operation. Sparse
`POST /admin/api/config/apply` updates persisted the NIM key and model. Admin
Apply does not authenticate NIM; the successful generation below supplies that
evidence. Configuration was reread after applying it, and no restart was needed.

The final model is FCC's original
`nvidia_nim/nvidia/nemotron-3-super-120b-a12b`. Cross-provider fallback and
per-Claude-tier overrides remain empty and process-owned. Proxy authentication
remains enabled, messaging remains disabled, and no NIM transport proxy is
configured. FCC remains running at `http://127.0.0.1:8082/admin`.

| Request          | Outcome                         |   Latency | Reported input/output tokens |
| ---------------- | ------------------------------- | --------: | ---------------------------: |
| Llama 3.1 8B     | HTTP 410; no generated response | 138.59 ms |                      Unknown |
| Nemotron 3 Super | HTTP 200; exact expected marker | 564.96 ms |                       27 / 8 |

Both authenticated `POST /v1/messages` requests used `stream:false` and
`max_tokens:32`, with a 60-second caller deadline and no client retry. The
Nemotron request explicitly disabled thinking. Llama 3.1 8B remained listed in
the catalog and official documentation, but its live request failed. The error
body was not retained, so this report does not assert why it returned HTTP 410.

FCC can retry a transient request up to five physical attempts. The token cap is
per attempt, and a caller deadline cannot prove immediate cancellation at NVIDIA.
Applying configuration also starts background model discovery. Therefore the
evidence counts two logical inference submissions, not an exact number of
upstream requests. No NVIDIA billing or free-tier balance was observed.

Sources: [NVIDIA model API catalog](https://docs.api.nvidia.com/nim/reference/llm-apis)
and the [audited FCC source](https://github.com/Alishahryar1/free-claude-code/tree/c9b75088b09cbd3251d1e828b710cfdcd1ff3c5a),
particularly `config/admin/persistence.py`, `runtime/provider_manager.py`,
`providers/nvidia_nim/request_options.py`, `providers/admission.py`,
`application/routing.py` and `api/request_lifetime.py`.

## Claude Code agent path

The installed Latchkit bridge and bounded process runner launched one Claude Code
session in a temporary fixture. The fixture contained a random marker absent
from the prompt. The task requested exactly one `Read` of that file and a final
response containing its marker. It passed in **two turns and 4.82 seconds**;
the process exited zero, the expected `Read` was observed, the marker matched,
the file digest was unchanged and no other workspace entry was created.

The invocation used `--model haiku`, `--tools Read`, `--max-turns 3`,
`--output-format stream-json`, `--verbose` and `--no-session-persistence`, with
normal provider permissions. Child-only environment settings requested a
512-token output cap and zero client retries. Latchkit enforced a 60-second
process deadline and 262,144-byte output limit. No global configuration was
written by the harness.

Claude Code reported **14,136 input tokens and 423 output tokens**. One local
usage record matches the actual provider, task and session ID. Its model label
is Claude's reported Haiku alias; the Nemotron route is established by FCC's
inspected configuration, pinned routing implementation and the owned local
connection. The label does not establish Anthropic inference or billing.
Cache counters are client observations through FCC, and actual billing remains
unknown. The usage summary was matched offline by session ID; no provider call
was repeated to correct that lookup.

The command flags and environment controls are documented in the
[Claude CLI reference](https://code.claude.com/docs/en/cli-reference) and
[environment-variable reference](https://code.claude.com/docs/en/env-vars).
Private harness commands executed under the installed Node runtime were:

```powershell
node .latchkit/qualify-fcc-nim.mjs probe
node .latchkit/qualify-fcc-nim.mjs apply
node .latchkit/qualify-fcc-nim.mjs infer
node .latchkit/qualify-fcc-nim.mjs apply nemotron
node .latchkit/qualify-fcc-nim.mjs infer nemotron
node .latchkit/qualify-fcc-claude.mjs
```

The first inference command exited one because of HTTP 410. The subsequent
configuration, Nemotron inference and Claude task commands exited zero.
An initial harness import path was corrected before its first successful probe;
that startup failure sent no inference request. These private harnesses are local
diagnostic artifacts, not a public release test command.
